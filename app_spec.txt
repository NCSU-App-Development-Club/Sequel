================================================================================
SHOWTHREAD - APP SPECIFICATION
A Reddit-Style Episode Discussion Platform for TV Shows & Movies
iOS 26 · SwiftUI · Liquid Glass · Swift 6.2
================================================================================

1. OVERVIEW
================================================================================

1.1 Product Vision
ShowThread is a native iOS discussion platform built for TV and movie fans who
want focused, episode-level conversations. Unlike Reddit's sprawling subreddit
model or Twitter's ephemeral timeline, ShowThread organizes every discussion
around a single episode (or a single movie), creating a natural home for
reactions, theories, and questions the moment new content drops.

The app is built from the ground up with SwiftUI on iOS 26, leveraging Apple's
Liquid Glass design language to deliver a visually stunning, platform-native
experience.

1.2 Problem Statement
- TV discussion is fragmented across Reddit megathreads, Twitter/X spoiler
  minefields, and siloed Discord servers.
- Existing platforms lack structured episode-level threading, making it hard to
  find discussion for a specific episode without spoilers.
- There is no dedicated, beautifully designed native iOS app for TV show
  discussion that takes full advantage of modern Apple design paradigms.

1.3 Target Audience
- Primary: TV enthusiasts aged 18–35 who actively discuss shows online and own
  iPhones.
- Secondary: Movie fans looking for a clean discussion space around new releases.
- Tertiary: Casual viewers who want to find where to watch a show and read
  reactions before committing.

1.4 Key Metrics
- Weekly Active Users: V1 target 10,000 / V2 target 75,000
- Avg Comments per Episode Thread: V1 target 25+ / V2 target 100+
- D7 Retention: V1 target 30% / V2 target 45%
- App Store Rating: V1 target 4.5+ / V2 target 4.7+


2. ARCHITECTURE & TECHNOLOGY STACK
================================================================================

2.1 Tech Stack
- Language: Swift 6.2 with strict concurrency checking enabled
- UI Framework: SwiftUI (iOS 26 SDK) — declarative UI with Liquid Glass APIs
- Local Persistence: SwiftData for structured data; @Observable models
- Networking: Swift concurrency (async/await), URLSession, Codable
- Image Loading: AsyncImage + Kingfisher for caching/prefetching
- Backend: Firebase (Auth, Firestore, Cloud Functions, Cloud Messaging)
- Content API: TMDB API v3 (show, season, episode, search, watch providers)
- Push Notifications: Firebase Cloud Messaging (FCM) via APNs
- Analytics: Firebase Analytics + Crashlytics
- Min Deployment: iOS 26.0

2.2 App Architecture
Modular MVVM with coordinator pattern for navigation. Each feature module is
isolated with its own View, ViewModel, and data layer. ViewModels are
@Observable classes that publish state to SwiftUI views and interact with
service layers via protocol-based dependency injection.

Module Breakdown:
- Core: shared models, APIClient, TMDB service, auth service, design tokens
- ShowsModule: show browsing, search, show detail, follow/unfollow
- EpisodesModule: episode list, episode thread, comment tree rendering
- CommentsModule: composing, voting, reply threading, sort engine
- WatchlistModule: My Shows tab, status management, notification bindings
- ProfileModule: user profile, karma, comment history, settings
- NotificationsModule: push handling, in-app notification center

2.3 Concurrency Model
Swift 6.2 strict concurrency fully adopted. All ViewModels are @MainActor.
Network and Firestore operations run on cooperative thread pools via async/await.
Sendable conformance enforced on all model types crossing isolation boundaries.
Actor-isolated service singletons (TMDBService, AuthService, VoteService)
prevent data races.


3. NAVIGATION STRUCTURE
================================================================================

3.1 Tab Bar
3-tab structure with Liquid Glass tab bar (shrinks on scroll, expands on
scroll-up):

Tab 1: Home      | SF Symbol: house.fill          | Personalized feed: trending, watchlist activity, recently aired, discover
Tab 2: My Shows  | SF Symbol: rectangle.stack.fill | Saved watchlist by status (Watching, Plan to Watch, Completed), search, discovery
Tab 3: Profile   | SF Symbol: person.fill          | Profile, comment history, karma, notifications, settings, account

3.2 Navigation Flow
Primary: Home → Show Detail → Episode Thread
Also: My Shows → Show Detail → Episode Thread
Push notifications deep-link to specific threads or comments.
All navigation uses NavigationStack with value-based programmatic routing.
Deep links: showthread://show/{tmdbId}/season/{n}/episode/{n}

3.3 Navigation Bar
- Large title on root views, collapsing to inline on scroll
- Show Detail: inline glass toolbar, back button morphs via matchedGeometryEffect
- Episode Thread: inline title with sort selector and compose button in toolbar


4. TAB 1: HOME SCREEN
================================================================================

4.1 Purpose
Primary entry point. Surfaces active discussions combining algorithmic ranking
with user preferences.

4.2 Layout Sections

Section A: Trending Now (Carousel)
- Horizontal scroll of 5–10 cards with highest comment velocity in 24h
- Each card: backdrop image, show title, episode label, comment count badge
- Tap navigates directly to episode thread

Section B: From Your Watchlist
- Vertical list of unvisited episode threads for followed shows, sorted by
  air date
- Unread indicator dot on each
- Empty state: "Save shows to see discussions here."

Section C: Recently Aired
- Threads for episodes aired in last 48 hours, sorted by comment count
- Covers unfollowed shows as discovery mechanism

Section D: Discover
- Editorial picks and breakout shows with high engagement-to-follower ratio
- Refreshed daily by Cloud Function analyzing trending velocity

4.3 Search
Persistent search bar below navigation bar. Full-screen search via TMDB
search/multi. Recent searches persisted locally. Trending searches shown
when empty.

4.4 Interactions
- Pull-to-refresh with Liquid Glass progress indicator
- Show cards have bookmark icon for quick-save to watchlist
- Long-press on show card: preview context menu (Save, Open, Share)


5. TAB 2: MY SHOWS SCREEN
================================================================================

5.1 Purpose
User's personal watchlist — centralized tracking of what they're watching,
plan to watch, and have completed. Primary launchpad for show detail and
episode discussions.

5.2 Status Segments
Liquid Glass segmented control at top with three statuses:
- Currently Watching (default on tab open)
- Plan to Watch
- Completed

5.3 Show List
Vertical list of show cards within selected status. Each card:
- Poster (60pt wide, 2:3 ratio), title, network, genre tags
- Next episode air date with countdown ("New episode in 3 days")
- Unread thread count badge
- Season progress: "5 of 10 episodes discussed"

Sort Options (Liquid Glass dropdown):
- Most Recent Activity (default)
- Alphabetical (A–Z)
- Next Airing (soonest first)

5.4 Adding Shows
- Search bar at top for TMDB search + add
- Floating "+" FAB (Liquid Glass interactive) triggers search/add
- On add, select status via bottom sheet: Watching, Plan to Watch, Completed
- Also addable from Show Detail page and bookmark icon on any show card

5.5 Managing Shows
- Swipe left: red "Remove" action with haptic confirmation
- Long-press: context menu — Change Status, Mute Notifications, Remove
- Status change moves show to new segment with list animation
- Removing unsubscribes from notifications

5.6 Empty States
- No shows saved: illustration + "Your watchlist is empty" + search button
- No shows in a status: "No shows here yet."

5.7 Offline
Watchlist cached locally via SwiftData. Show metadata and posters cached on
first load. Unread counts stale-indicated offline.


6. TAB 3: PROFILE SCREEN
================================================================================

6.1 Profile Header
- Avatar: 80pt circular image. Tap to change (camera, library, defaults)
- Display name: tappable to edit (unique, 3–20 chars, alphanumeric + _)
- Bio: 160 char max, tappable to edit
- Karma score with upvote icon. Tap for breakdown (up, down, net)
- Joined date + show count ("Tracking 12 shows")

6.2 Comment History
- Paginated list, most recent first
- Each row: show title, episode label, comment preview (2 lines), timestamp,
  net votes
- Tap navigates to thread and scrolls to comment

6.3 Notifications Center
- In-app notifications grouped by show, sorted reverse-chronologically
- Types: replies, new episode threads (followed shows), trending, karma
  milestones
- Badge on Profile tab for unread. Each notification deep-links.

6.4 Settings
- Notification prefs: global toggles + per-show overrides + quiet hours
- Appearance: system / light / dark mode
- Spoiler protection: "caught up through" per show
- Account: change email/password, sign out, delete account
- About: version, TMDB attribution, streaming attribution, licenses

6.5 Authentication
- Sign in with Apple (primary), email + password, Google Sign-In
- Face ID / Touch ID for returning sessions
- Unauthenticated: browse and read only (no comment, vote, or save)


7. SHARED SCREENS
================================================================================

7.1 Show Detail
- Hero backdrop (16:9, gradient fade), title, year, network, genre glass chips,
  TMDB rating, status
- Streaming links as tappable Liquid Glass pills
- Save/status button with dropdown
- Season selector: horizontal glass pills
- Episode list per season: number, title, air date, comment count, still

7.2 Episode Thread
Header:
  - Still image (16:9), episode title, S/E label, air date, runtime
  - Expandable overview, streaming links row

Sort Control:
  - Liquid Glass segmented: Hot (default), Top (Today/Week/All), New,
    Controversial

Sort Algorithms:
  - Hot: Wilson score confidence interval weighted by recency
  - Top: Highest net upvotes. Sub-filters: Today, This Week, All Time
  - New: Reverse chronological by creation timestamp
  - Controversial: High total votes but net score near zero

Comment Tree:
  - Nested via flat LazyVStack, 16pt/level indentation, max depth 5
  - Each comment: avatar (24pt), name, karma badge, timestamp, body,
    vote arrows + score, reply button
  - Collapsed threads: "12 more replies" tappable to expand
  - Spoiler-tagged text: blurred blocks, tappable to reveal

Compose Bar:
  - Floating Liquid Glass bar: "Join the discussion..." placeholder
  - Tap expands to full glass sheet: multiline editor, spoiler tag button,
    submit
  - Reply: composer pre-filled with parent context

Voting System:
  - Each comment: upvote and downvote buttons flanking net score
  - One vote per user per comment: up, down, or neutral (tap again to remove)
  - Optimistic UI updates, server-side persistence
  - Vote animations: .symbolEffect(.bounce) + UIImpactFeedbackGenerator(.light)
  - Users cannot vote on own comments
  - Votes contribute to commenter's karma

7.3 Streaming Availability
- Supported V1: Netflix, Hulu, Disney+, HBO Max, Prime Video, Apple TV+,
  Peacock, Paramount+, Crunchyroll
- Tap opens app via universal link or falls back to web URL
- Region-aware via device App Store region
- Attribution: "Streaming data provided by JustWatch via TMDB"

7.4 Spoiler Protection
- Inline: >!text!< syntax renders as blurred block, tappable to reveal
- Thread warning: episodes aired < 48h ago show prominent spoiler banner
- Season-gated: "caught up through" setting gates future episode threads


8. DATA MODELS
================================================================================

All models conform to Codable, Identifiable, and Sendable. SwiftData @Model
types for local persistence. Firestore documents map 1:1 via Codable.

8.1 Show (@Model)
Fields: tmdbId (unique Int), title, overview, posterPath?, backdropPath?,
genres [String], networks [String], status (ShowStatus), firstAirDate?,
voteAverage (Double), mediaType (MediaType), seasonCount, lastRefreshed,
followerCount. Relationship: seasons [Season] (cascade delete).

Enums: ShowStatus (.airing, .ended, .upcoming, .cancelled),
MediaType (.tvShow, .movie)

8.2 Season (@Model)
Fields: id (unique, "{tmdbId}_S{n}"), showTmdbId, seasonNumber, name,
overview?, posterPath?, airDate?, episodeCount.
Relationships: episodes [Episode] (cascade), show: Show?

8.3 Episode (@Model)
Fields: id (unique, "{tmdbId}_S{n}E{n}"), showTmdbId, seasonNumber,
episodeNumber, name, overview?, stillPath?, airDate?, runtime? (minutes),
guestStars [String], commentCount.
Relationship: season: Season?

Note: Movies → single Episode (seasonNumber=1, episodeNumber=1)

8.4 Comment (struct, Firestore)
Fields: id, authorId, authorDisplayName, authorAvatarURL?, authorKarma,
episodeId, parentCommentId? (nil=top-level), body, upvoteCount, downvoteCount,
netScore (computed), createdAt, editedAt?, isDeleted, depth (0=top, max 5)

8.5 Vote (struct, Firestore)
Fields: id ("{commentId}_{userId}"), commentId, userId,
value (VoteValue: .up=+1, .down=-1), createdAt

8.6 UserProfile (struct, Firestore)
Fields: id (Firebase UID), displayName, avatarURL?, bio?, karma, joinedAt,
favoriteShowIds [Int], notificationPreferences (NotificationPrefs)

NotificationPrefs: repliesEnabled, newEpisodesEnabled, trendingEnabled,
karmaEnabled, quietHoursStart?, quietHoursEnd?, mutedShowIds [Int]

8.7 WatchlistEntry (@Model + Firestore)
Fields: id ("{userId}_{tmdbId}"), userId, tmdbId, status (WatchStatus),
dateAdded, lastVisited?, notificationsEnabled (default true).
Relationship: show: Show?

WatchStatus: .watching, .planToWatch, .completed

8.8 StreamingLink (struct)
Fields: id (TMDB provider ID), providerName, logoPath, webURL, universalLinkURL?,
type (StreamingType: .flatrate, .rent, .buy)

8.9 AppNotification (struct, Firestore)
Fields: id, userId, type (NotificationType: .reply, .newEpisode, .trending,
.karmaMilestone), title, body, showTmdbId?, episodeId?, commentId?, createdAt,
isRead

8.10 Sort Enums
- CommentSortMode: .hot, .top, .new, .controversial
- TopTimeFilter: .today, .thisWeek, .allTime
- ShowListSortMode: .recentActivity, .alphabetical, .nextAiring


9. TMDB INTEGRATION & CONTENT DATA
================================================================================

9.1 API Endpoints
- GET /search/multi — search shows/movies (debounced 300ms)
- GET /tv/{id} — show details + append seasons (first visit + 6h refresh)
- GET /tv/{id}/season/{n} — season with episodes (on selection)
- GET /movie/{id} — movie details (first visit)
- GET /tv/{id}/watch/providers — streaming availability (on detail load)
- GET /trending/tv/day — trending for Discover (cached 1h)
- GET /configuration — image base URL (cached 24h)

9.2 Batching
append_to_response: up to 20 sub-requests per call. Show detail batches
seasons, watch/providers, credits. >20 seasons → second call.

9.3 Movie Normalization
Movie → Show (mediaType=.movie) → Season (seasonNumber=1) → Episode
(episodeNumber=1). Single content hierarchy, no branching logic.

9.4 Image Handling
- Poster: w342 (lists), w500 (detail)
- Backdrop: w780 (hero), w300 (cards)
- Still: w300 (lists), w780 (thread header)
- Kingfisher: 200MB disk (7-day TTL), 50MB memory
- Prefetch episode stills on season selection

9.5 Sync & Refresh
- On-demand fetch on first visit
- Cloud Function refreshes airing shows every 6h
- Stale detection: lastRefreshed > 6h → background refresh
- New episode → thread creation in Firestore + push to followers


10. PERSISTENCE & STORAGE
================================================================================

10.1 Local (SwiftData)
- Show metadata: 6h TTL, LRU eviction after 500, ~2MB
- Season/Episode: 6h TTL, cascade with Show, ~5MB
- WatchlistEntry: no expiry, user-managed, <1MB
- Comment drafts: no expiry, deleted on submit, <1MB
- Recent searches: 30-day TTL, max 50, <0.1MB

10.2 Remote (Firestore)
- users/{userId} — UserProfile
- users/{userId}/watchlist/{tmdbId} — WatchlistEntry
- shows/{tmdbId} — cached metadata + followerCount
- shows/{tmdbId}/episodes/{sNum}_{eNum} — episode + commentCount
- comments/{commentId} — Comment
- votes/{commentId}_{userId} — Vote
- notifications/{notificationId} — AppNotification

10.3 Image Cache (Kingfisher)
- Disk: 200MB max, 7-day TTL, Caches directory
- Memory: 50MB max, evicted on memory pressure
- Prefetch: episode stills for selected season

10.4 Real-Time Sync
- Firestore snapshot listeners on active thread for live comments
- Document-level listeners for live vote counts
- Watchlist: bidirectional SwiftData ↔ Firestore sync

10.5 Offline
- Watchlist + show metadata fully available offline
- Comments cached per-thread with staleness indicator
- New comments/votes queued in local outbox, replayed on reconnect (FIFO)
- Draft comments persisted locally, never lost


11. UI/UX DESIGN SPECIFICATIONS
================================================================================

11.1 Liquid Glass Design System
Principle: glass is for chrome, not for content. Glass on navigation layer
(toolbars, tab bars, floating controls, sheets). Content on opaque surfaces.

Component Mapping:
- Tab Bar: default iOS 26 shrink/expand behavior (TabView auto glass)
- Navigation Bar: glass toolbar, morphs compact (.navigationBarTitleDisplayMode)
- Sort Selector: segmented with sliding glass pill (.glassEffect + .glassEffectID)
- Compose Bar: floating glass, morphs to sheet (GlassEffectContainer)
- Streaming Chips: interactive glass pills (.buttonStyle(.glass))
- Vote Arrows: glass circles, interactive ripple (.glassEffect(.interactive))
- Season Picker: horizontal glass pills (.glassEffectID in namespace)
- FAB (My Shows): circular glass + icon (.glassEffect(.interactive))
- Status Segments: glass segmented control (Picker + .glassEffect)

11.2 Colors
- Surfaces: system background (auto light/dark)
- Cards: .secondarySystemGroupedBackground
- Accent: warm indigo (#6C5CE7) for votes, badges, interactive states
- Destructive: system red
- Text: .label / .secondaryLabel / .tertiaryLabel
- No hardcoded hex in views. Full dark mode via semantic colors.

11.3 Typography
- SF Pro throughout with Dynamic Type
- Show titles: .title2 .bold
- Episode titles: .headline
- Comment body: .body
- Metadata: .caption .medium + .secondaryLabel

11.4 Spacing
- Padding: 16pt horizontal, 12pt vertical
- Comment indent: 16pt/level (max 80pt at depth 5)
- Card corners: 12pt (show), 8pt (comment)
- Avatars: 80pt (profile), 40pt (detail), 24pt (inline)
- Touch targets: 44×44pt minimum

11.5 Animations & Haptics
- Vote: .symbolEffect(.bounce) + UIImpactFeedbackGenerator(.light)
- Save: .symbolEffect(.bounce) + .medium haptic
- New comment: .move(edge:.top) + .opacity with .spring
- Sort change: .contentTransition(.symbolEffect(.replace))
- Compose expand: GlassEffectContainer morph (auto via glassEffectID)
- Nav transitions: matchedGeometryEffect (show card → hero)

11.6 Accessibility
- VoiceOver labels + hints on all interactive elements
- Dynamic Type: xSmall through AX5
- Reduce Transparency: opaque fallback for glass
- Reduce Motion: .easeInOut(0.25) fallback, suppress symbol effects
- Minimum contrast: 4.5:1
- VoiceOver rotor: top-level comments as headings


12. NON-FUNCTIONAL REQUIREMENTS
================================================================================

12.1 Performance
- Cold launch: < 2s on iPhone 14+
- Thread scroll: 60fps at 500+ comments
- Search: < 1s from keystroke (300ms debounce)
- Images: < 500ms on Wi-Fi with shimmer placeholder
- Comment write: optimistic UI < 50ms, server confirm < 2s

12.2 Reliability
- Crash-free rate: > 99.5%
- Offline queue: guaranteed delivery with exponential backoff
- TMDB failures: graceful degradation to cache + "Content may be outdated"
- Timeouts: 10s API, 30s images, max 2 retries

12.3 Security
- Firebase Auth for token management
- Firestore rules: users write only own data, 1 vote per comment
- HTTPS (TLS 1.3)
- API keys in Info.plist (excluded from SCM)
- No PII in analytics

12.4 Scalability
- Firestore auto-scales for V1 (10K WAU)
- TMDB: ~40 req/10s with batching + caching (75K WAU)
- Comment pagination: 50-comment batches with cursor queries
- TMDB CDN for image delivery

12.5 Compliance
- TMDB: "This product uses the TMDB API but is not endorsed or certified
  by TMDB" + logo
- JustWatch: "Streaming data provided by JustWatch via TMDB" footnote
- App Store Guidelines 4.0, 5.0, Sign in with Apple
- Privacy nutrition label. No third-party trackers.
- GDPR/CCPA: account deletion (comments anonymized)


13. MODERATION & COMMUNITY SAFETY
================================================================================

13.1 Content Moderation
- Perspective API toxicity scoring on submit (threshold 0.8 → held for review)
- User reporting via long-press: spam, harassment, spoilers, off-topic
- Admin dashboard: Firebase Admin SDK web app (queue + approve/reject/ban)

13.2 Account Actions
- Mute: hides user's comments client-side
- Block: mute + prevents replies (Firestore rules)
- Bans: 24h, 7d, 30d (temporary) or permanent
